4 THÀNH PHẦN CỐT LÕI CỦA ỨNG DỤNG QUẢN LÝ TÀI LIỆU

🎨 1. Frontend (Giao diện người dùng)

Flutter đa nền tảng (Web & Windows Desktop).

  • Sidebar điều hướng màu hồng đặc trưng của Cashew.
  • Kho tài liệu 3 Tabs: Bài giảng, Bài tập, Tài liệu tham khảo.
  • Tìm kiếm thời gian thực, gắn màu môn học, hộp thoại Cloud Modal.

⚙️ 2. Backend (Tầng xử lý logic nghiệp vụ)

Mô hình Client-Side Business Logic + Cloud REST Client.

  • Xử lý kiểm tra dữ liệu, sắp xếp ưu tiên Pinned, lọc đa tiêu chí.
  • Hàng đợi đồng bộ SyncQueue quản lý cờ trạng thái isSynced.
  • Xử lý ngoại tuyến và đồng bộ nền 2 chiều lên đám mây.

🗄️ 3. Database (Cơ sở dữ liệu có cấu trúc)

Local DAO Layer + Google Cloud Firestore (NoSQL).

  • Lưu trữ metadata: ID, tiêu đề, mã môn học, tags, deadline.
  • Cơ chế Reactive Streams thông báo UI thay đổi ngay lập tức.
  • Đồng bộ lên Firestore Collection study_documents.

📁 4. File Storage (Lưu trữ tệp tin nhị phân)

Local File System + Firebase Cloud Storage Bucket.

  • Lưu các tệp dung lượng lớn: PDF slide, DOCX bài tập, tệp nén ZIP.
  • Lưu URL tải về an toàn kèm mã xác thực Token.
  • Phân quyền thư mục theo định danh người dùng: /study_docs/{userId}/.
🎙️ Lời thoại thuyết trình: "Ứng dụng được cấu thành từ 4 khối chính: Frontend Flutter mượt mà, Backend xử lý logic cục bộ và client sync, Database lưu thông tin metadata có cấu trúc, và File Storage chuyên biệt lưu các tệp slide, bài tập nặng."

CÁC ĐIỂM NGHẼN CỦA HẠ TẦNG TRUYỀN THỐNG (LOCAL/ON-PREMISE)

❌ Hạn chế vận hành cục bộ (Local-Only)

  • Mất mát dữ liệu hoàn toàn: Khi máy tính hỏng ổ cứng hoặc cài lại hệ điều hành, toàn bộ giáo trình và bài tập tích lũy bị mất.
  • Không đồng bộ thiết bị: Sinh viên lưu bài giảng trên laptop nhưng lên lớp dùng điện thoại thì không có file để học.
  • Tràn bộ nhớ thiết bị: Các file tài liệu slide PDF nặng chiếm hết bộ nhớ trong của điện thoại.

⚠️ Thách thức khi tự dựng Server riêng (On-Premise)

  • Chi phí phần cứng & bảo trì: Mua máy chủ, đăng ký IP tĩnh, duy trì tiền điện và điều hòa 24/7 quá tốn kém.
  • Nghẽn băng thông giờ cao điểm: Khi đến mùa thi, hàng trăm sinh viên cùng tải đề tài sẽ làm sập máy chủ.
  • Lỗ hổng an ninh mạng: Khó tự vá các lỗi bảo mật mạng, nguy cơ bị rò rỉ tài liệu và bài tập.
🎙️ Lời thoại thuyết trình: "Vận hành trên hạ tầng cũ hoặc chỉ lưu trên một máy gây ra 2 rủi ro lớn: thứ nhất là mất trắng dữ liệu khi hỏng máy, và thứ hai là không thể học tập linh hoạt trên nhiều thiết bị."

Checklist 4 • Luồng dữ liệu giữa Client & Cloud Trang 06

MÔ TẢ LUỒNG DỮ LIỆU ĐỒNG BỘ HAI CHIỀU

  • Bước 1 (Ghi cục bộ): Sinh viên tạo tài liệu mới kèm tệp bài tập. Dữ liệu được ghi ngay lập tức vào bộ nhớ cục bộ, cờ isSynced = false. UI phản hồi tức thì 0ms.
  • Bước 2 (Kiểm tra mạng & Xếp hàng đợi): Hệ thống đẩy tác vụ vào hàng đợi SyncQueue. Nếu thiết bị Offline, tác vụ được giữ an toàn trong hàng đợi.
  • Bước 3 (Đẩy tệp tin lên Cloud Storage): Khi có mạng, tệp tài liệu được tải lên Firebase Storage: /study_docs/{userId}/{fileName}, nhận về URL tải an toàn.
  • Bước 4 (Đồng bộ Metadata lên Firestore): StudySyncClient gửi REST request lên Firestore cập nhật document và cập nhật cờ isSynced = true.
  • Bước 5 (Kéo dữ liệu mới về): Client gửi truy vấn lấy các bản ghi có lastModified mới hơn trên Cloud để cập nhật vào máy cá nhân theo giải thuật Last-Write-Wins (LWW).
🎙️ Lời thoại thuyết trình: "Luồng dữ liệu tuân thủ tuyệt đối nguyên tắc Local-First: luôn ưu tiên lưu vào máy trước để người dùng không phải chờ đợi mạng xoay vòng, sau đó tiến trình đồng bộ nền sẽ đẩy tệp lên Storage và metadata lên Firestore."
Checklist 5 • Đánh giá tác động Trang 07

ĐÁNH GIÁ TÁC ĐỘNG: BẢO MẬT, CHI PHÍ & HIỆU SUẤT

🔒 1. Bảo mật dữ liệu

  • Mã hóa dữ liệu 100% khi truyền tải (HTTPS/TLS) và khi lưu trữ (AES-256).
  • Kiểm soát quyền truy cập chặt chẽ qua Firestore & Storage Security Rules.
  • Chỉ chủ sở hữu (auth.uid) mới có quyền đọc và ghi tài liệu của mình.

💰 2. Chi phí tối ưu

  • Chi phí 0 VNĐ cho quy mô bài tập lớn môn học nhờ gói Spark Plan.
  • 1 GiB lưu trữ NoSQL (đủ cho 1.000.000 bản ghi tài liệu học tập).
  • 5 GiB Cloud Storage (chứa hơn 2.500 file slide PDF thông thường).

⚡ 3. Hiệu suất vượt trội

  • Độ trễ thao tác trên UI = 0ms (nhờ kiến trúc Local-First).
  • Băng thông mạng phân phối toàn cầu qua CDN Google Cloud Platform.
  • Tự động co giãn (Auto-scaling) đáp ứng hàng ngàn sinh viên truy cập cùng lúc.

Tìm hiểu công nghệ • Hệ sinh thái Firebase Trang 08

TÌM HIỂU VỀ NỀN TẢNG GOOGLE FIREBASE

Google Firebase là nền tảng Backend-as-a-Service (BaaS) hàng đầu thế giới do Google cung cấp, mang lại giải pháp toàn diện cho ứng dụng di động và web:

🔥 Các dịch vụ sử dụng trong dự án:

  • Firebase Authentication: Cung cấp giải pháp đăng nhập bảo mật với Google, Email, Facebook mà không cần viết server backend.
  • Cloud Firestore: Cơ sở dữ liệu NoSQL phân tán thời gian thực, tự động lập chỉ mục truy vấn và hỗ trợ offline persistence.
  • Cloud Storage: Kho lưu trữ tệp tin nhị phân dựa trên Google Cloud Storage, độ sẵn sàng 99.999999999% (11 số 9).

💡 Ưu thế nổi bật cho ứng dụng:

  • Tích hợp chặt chẽ với hệ sinh thái Flutter thông qua bộ thư viện FlutterFire chính chủ.
  • Hỗ trợ REST API tiêu chuẩn, chạy mượt trên Web và Windows Desktop mà không cần thư viện native C++.
  • Bảo mật đa tầng bằng ngôn ngữ Declarative Rules (Security Rules).
🎙️ Lời thoại thuyết trình: "Firebase đóng vai trò là một Backend hoàn chỉnh dạng dịch vụ (BaaS). Thay vì nhóm phải tự viết một server NodeJS hay Spring Boot tốn nhiều tuần lễ, Firebase cung cấp sẵn toàn bộ hạ tầng xác thực, cơ sở dữ liệu và lưu trữ file."
Checklist 6 • Quy trình Setup theo chuẩn Google Trang 09

QUY TRÌNH SETUP FIREBASE THEO CHUẨN FLUTTER

Theo tài liệu chính thức của Google (firebase.google.com/docs/flutter/setup?hl=vi), quy trình tích hợp gồm 4 bước chuẩn hoá:

# 1. Cài đặt Firebase CLI (Yêu cầu Node.js) npm install -g firebase-tools # 2. Đăng nhập vào tài khoản Google firebase login # 3. Kích hoạt FlutterFire CLI toàn cục dart pub global activate flutterfire_cli # 4. Tự động liên kết dự án Flutter với Project Firebase flutterfire configure --project=study-document-cloud

✨ Lệnh flutterfire configure sẽ tự động đăng ký các ứng dụng Web/Android/iOS vào Firebase Console và sinh ra tệp lib/firebase_options.dart chuẩn xác!

🎙️ Lời thoại thuyết trình: "Theo tài liệu chính thức từ Google, quy trình setup cho Flutter hiện nay vô cùng nhanh chóng thông qua FlutterFire CLI, chỉ với 4 dòng lệnh là mã nguồn Flutter đã được liên kết với Firebase."

MÃ NGUỒN TÍCH HỢP ĐĂNG NHẬP GOOGLE & STORAGE

1. Đăng nhập Google (Google Sign-In):

Future<UserCredential> signInWithGoogle() async { final GoogleSignInAccount? gUser = await GoogleSignIn().signIn(); final GoogleSignInAuthentication gAuth = await gUser!.authentication; final credential = GoogleAuthProvider.credential( accessToken: gAuth.accessToken, idToken: gAuth.idToken, ); return await FirebaseAuth.instance .signInWithCredential(credential); }

2. Tải tệp tin lên Firebase Storage:

Future<String> uploadDocumentFile(File file, String name) async { final uid = FirebaseAuth.instance.currentUser!.uid; final ref = FirebaseStorage.instance .ref('study_docs/$uid/$name'); final task = await ref.putFile(file); return await task.ref.getDownloadURL(); }
